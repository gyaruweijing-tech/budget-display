# フロントエンドに秘密を置くな — 銀行残高アプリのAPIトークン流出を直した話

> 自作の月次予算アプリ（React + Vite + Vercel）で、銀行残高を取得するための「合言葉（トークン）」を**フロントエンドに置いてしまい、世界中に丸見えだった**問題を見つけ、サーバーレス関数を使って正しく隠すまでの記録。
> 初学者がハマりやすい「環境変数＝安全」という誤解を、実例で解きほぐす。

---

## 0. 3行まとめ

- **ブラウザで動くコード（フロント）は、世界中に公開されている。** だから秘密を置くと必ず漏れる。
- **環境変数は「ソースコードに秘密を書かない」ためのもので、「ユーザーに秘密を見せない」保証ではない。** Vite の `VITE_` 付き変数はビルド時にJSへ焼き込まれて公開される。
- 本当に隠すには、**秘密を使う処理をサーバー側（サーバーレス関数）に移す**。ブラウザはその関数を呼ぶだけにする。

---

## 1. 何が起きていたか

予算アプリには「銀行の残高を表示するカード」があった。仕組みはこう：

- Google Apps Script (GAS) を Web API として公開し、URLに**合言葉（トークン）**を付けて叩くと残高を JSON で返す。
- React 側は、その URL とトークンを使って残高を取りに行く。

React のコードはこうなっていた：

```jsx
// ❌ Before（あぶない）
const GAS_URL   = import.meta.env.VITE_GAS_URL;
const GAS_TOKEN = import.meta.env.VITE_GAS_TOKEN;

// ...ブラウザから直接、合言葉付きでGASを叩く
const url = `${GAS_URL}?token=${GAS_TOKEN}`;
const res = await fetch(url);
```

「トークンは Vercel の環境変数に入れてるから安全」と思っていた。**これが誤解だった。**

### 実際に漏れていた証拠

公開サイトで `F12`（開発者ツール）→ **Sources** タブ → `assets` フォルダの中の `index-XXXX.js` を開いて検索すると、こう書いてあった：

```js
// 公開されているJSバンドルの中身（誰でも読める）
g = "https://script.google.com/macros/s/AKfyc.../exec"   // GASのURL
_ = "<あなたのトークン>"                                    // 合言葉そのもの
```

**URLを知っている人なら誰でも、この合言葉を拾って残高・取引履歴を読める状態だった。**
（幸い GAS は読み取り専用だったので「見られるだけ・お金は盗めない」リスクだったが、それでも個人情報は丸見え。）

---

## 2. なぜ漏れるのか — 一番大事な概念

### フロントエンドのコードは「公開物」

Web サイトは3つの部品でできている：

| 言語 | 役割 | たとえ |
|---|---|---|
| HTML | 骨組み・構造 | 建物の骨格 |
| CSS | 見た目 | 内装・塗装 |
| **JavaScript** | 動き・頭脳 | 電気・スイッチ |

ブラウザは、JS を**ダウンロードして実行する**。つまり**ユーザーの手元に必ずコードが渡る**。
だから「フロントのコードは、見ようと思えば誰でも全部読める」のが大前提。

> **判断基準はこれひとつ：**
> 「このフロントのコード、世界中に見せても平気か？」
> - YES → セキュリティOK
> - NO（秘密が入っている）→ 漏れている

「安心して人に見せられる＝正しくできている」。逆に「見せられない」なら、それ自体がアウトのサイン。

---

## 3. 環境変数の正体（誤解を解く）

### 環境変数は何のためにある？

1. **コードはGitで共有される。** 秘密を直接書くと、push した瞬間に漏れる。だから値はコードの外（環境変数）に出す。
2. **同じコードを環境ごとに違う値で動かす**（開発/本番でURLを変える等）ため。

つまり環境変数が保証するのは **「ソースコードに秘密を埋め込まない」だけ。**
**「その秘密がユーザーのブラウザに届かない」ことは保証しない。** ← ここが落とし穴。

> **たとえ話**：環境変数は、鍵を「コードに直書き（玄関にテープで貼る）」じゃなく「ラベル付きの引き出しにしまう」こと。引き出しにしまったのは偉い。でもアプリがその鍵を**コピーして訪問者全員に配って**いたら（＝フロントに焼き込んでいたら）、意味はゼロ。

### 環境変数は2種類ある

| | どこで使われる | ブラウザに届く？ | 安全？ |
|---|---|---|---|
| **クライアント用** | フロントのJS（Vite: `VITE_` / Next.js: `NEXT_PUBLIC_`） | **届く（ビルド時にJSへ焼き込み）** | ❌ 誰でも見れる |
| **サーバー用** | サーバーレス関数・APIの中だけ（接頭辞なし） | 届かない（サーバーに留まる） | ✅ 見れない |

ポイント：
- **Vercel が値を保管する場所自体は安全**（暗号化されている）。
- 漏れるのは**「ビルド時にフロントのJSへ焼き込まれた瞬間」だけ**。
- **純粋なフロントだけのアプリ（Vite SPA）にはサーバーが無い**ので、キーを使うには焼き込むしかない → 必ず漏れる。

---

## 4. 自分が漏らしているか確認する方法（30秒）

1. 公開サイトを開く → `F12`（開発者ツール）→ **Sources** か **Network**
2. JSファイル（`index-XXXX.js`）を開く
3. `Ctrl + F` で**トークンの値**や**変数名（`VITE_` で始まるもの）**を検索
4. ヒットしたら**漏れている**。`VITE_` / `NEXT_PUBLIC_` 接頭辞は「フロントに出す」という意味なので、ほぼ確実に焼き込まれる。

---

## 5. 直し方

修正は2段階。**A：漏れた鍵を無効化 → B：正しく隠す。**

### A. トークンのローテーション（漏れた合言葉を無効化）

「ローテーション」＝**合言葉を新しいものに付け替えるだけ**（ドアの暗証番号を変えるのと同じ）。

1. 新しい合言葉を**手元で**生成（チャットやどこにも貼らない）：
   ```bash
   node -e "console.log(require('crypto').randomBytes(12).toString('hex'))"
   ```
2. GAS のコードの該当1行を書き換える：
   ```js
   const TOKEN = '<新しい合言葉>';   // ← ここだけ変える
   ```
3. **GASは「コードを保存」しただけでは反映されない。** Web アプリは「下書き」と「公開中の版」が別物。
   `デプロイ → デプロイを管理 → 既存のを✏️編集 → バージョン「新しいバージョン」→ デプロイ`
   （**「新しいデプロイ」を押すとURLが変わる**ので、必ず既存を編集する。URLは据え置きで中身だけ更新される）

→ この瞬間、**漏れていた古い合言葉は無効化**される。

> GAS あるある：「コード変えたのに直らない」は、ほぼ**新バージョンをデプロイし忘れ**。

### B. サーバーレス関数で「ちゃんと隠す」

秘密を**サーバー側で動く中継コード（受付係）**に持たせ、ブラウザはそれを呼ぶだけにする。

**Before / After の構造：**

```
Before： ブラウザ ──(合言葉つき)──► GAS          ← 合言葉が世間に丸見え
After ： ブラウザ ──► 受付係(Vercel関数) ──(合言葉つき)──► GAS
                       ↑ここが新登場              ← 合言葉は受付係の中だけ
```

#### B-1. Vercel サーバーレス関数を追加

プロジェクト直下に `api/balance.js` を作る（Vercel は `api/` フォルダを自動でサーバーレス関数として扱う）：

```js
// api/balance.js — Vercelのサーバー上で実行される（ブラウザには中身が出ない）
// 秘密(GAS_URL / GAS_TOKEN)はここでだけ使う。VITE_ を付けないのがミソ。
export default async function handler(req, res) {
  const GAS_URL = process.env.GAS_URL;
  const GAS_TOKEN = process.env.GAS_TOKEN;
  if (!GAS_URL || !GAS_TOKEN) {
    return res.status(500).json({ error: "サーバー側の環境変数が未設定です" });
  }
  try {
    const url = `${GAS_URL}?token=${encodeURIComponent(GAS_TOKEN)}`;
    const r = await fetch(url);
    return res.status(200).json(await r.json());
  } catch (e) {
    return res.status(502).json({ error: String(e.message || e) });
  }
}
```

#### B-2. フロントは「受付係を呼ぶだけ」に変更

```jsx
// ✅ After（あんしん）— 秘密の参照を全部削除
const res = await fetch("/api/balance");   // トークンを一切持たない
const json = await res.json();
```

#### B-3. Vercel に「サーバー用」環境変数を登録

ダッシュボード → **Settings → Environment Variables** で：

- `GAS_URL` = GASの `/exec` URL（**VITE_なし**）
- `GAS_TOKEN` = **新しい合言葉**（**VITE_なし**）
- 旧 `VITE_GAS_URL` / `VITE_GAS_TOKEN` は削除

> 名前は**完全一致**で（`process.env.GAS_TOKEN` と一字一句同じ）。`VITE_` を付けるとまたフロントに漏れるので絶対に付けない。

#### B-4. デプロイ＆検証

- GitHub に push（Vercel 連携なら自動デプロイ）。
- 公開サイトの JSバンドルを再検索 → **トークンも GAS URL も出てこない**。`fetch("/api/balance")` だけが残る。
- 残高がちゃんと表示される＝ブラウザ → 受付係 → 新しい合言葉でGAS、の全経路が動いている。

---

## 6. ローカル開発の注意

- 普通の `vite`（`npm run dev`）では `/api/*` は存在しない（サーバーレス関数が動かない）。
- 関数込みでローカル確認したいときは **`npx vercel dev`** を使う。
- ローカル用の秘密は `.env.local`（`.gitignore` で除外）に、**`VITE_` なしの名前**で置く。

## 7. やりがちな誤解 vs 正解

| 誤解 | 正解 |
|---|---|
| 環境変数に入れたから安全 | 環境変数は「コードに直書きしない」だけ。フロントに焼き込まれたら公開される |
| Vercelが保管してるからサーバー側＝安全 | 保管は安全。でも**ビルドでJSに入った瞬間**に公開される |
| minify（圧縮）されてて読めないから大丈夫 | 変数名は短くなるが、**文字列（URL・トークン・金額）はそのまま残る** |
| 合言葉(トークン)があるから安全 | 公開ビルドに焼き込まれたトークンは防御にならない |

---

## 8. 残る注意点（ここまでやっても）

- **サーバーレス関数のエンドポイント自体は公開**されている。鍵は見えなくなったが、`/api/balance` は誰でも叩ける。
  本気で守るなら **レート制限** や **簡易パスワード/認証** を足す。
- 今回のように **読み取り専用 & 低リスク**なら、まずは「鍵を隠す」だけでも大きな前進。
- **「データ」と「秘密」は別物**：残高や取引履歴（個人情報）は隠す対象だが、APIキーのような「鍵」とは性質が違う。鍵は絶対に隠す、データはプライバシーの好みで判断。

### あとがき

「環境変数に入れたから安全」は、多くの初学者（と、ときに経験者）がハマる罠。
本質は **「ブラウザに渡るものは、全部世界に渡る」**。
だからこそ——**安心して他人に見せられるコードかどうか**が、そのままセキュリティの答え合わせになる。
